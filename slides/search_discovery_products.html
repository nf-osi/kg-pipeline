From Framework To Portal Copilot

Synapse Custom Agent translation and impact over time

The NF Portal Assistant (and any other Portal Copilots) is built on top of the Synapse Custom Agent framework. This timeline shows how the platform, benchmarking work, collaboration prototypes, and hackathon deployments have built toward the current product.

Nov 2024

Synapse Custom Agent design doc available

The platform-level design for custom agents, chat sessions, worker invocation, and Bedrock-backed orchestration becomes concrete and shareable. Design doc.

Feb 2025

Planning and benchmarking data prep start in nf-osi/portal-chatbot

Portal-specific work begins with planning, evaluation design, and benchmark creation to measure assistant quality against realistic research questions.

May 2025

Netrias custom agent implemented for BDF collaboration prototype

A concrete collaboration prototype demonstrates Custom Agent usage beyond design documentation and helps validate cross-team delivery patterns.

Dec 2025

Hackathon deployment of the NF Portal Assistant

The NF Portal Assistant reaches the portal with a new UI component and a new navigation feature, shifting from internal development into user-facing experience work.

Mar 2026

Assistant expands to graph KB, publications, and <guideprompt>

The assistant gains deeper retrieval by integrating the graph knowledge base and publication content, while the <guideprompt> feature adds more structured guidance for the next user step.

Why these do not work with OpenSearch

Each prompt depends on assistant behaviors that go beyond fast ranked retrieval over indexed metadata.

  • Cross-source synthesis: the answer needs information to be connected across entities and to other sources like literature.
  • Personalization and domain understanding: needs implict interpretation of question and results, comparative judgment.
  • Reasoning: the assistant has to "do research" to find the right answer, which requires analytical steps.
  • Guided action: useful output includes explanation and suggested next steps.

Portal Search & Discovery Strategy

OpenSearch and an AI Portal Copilot solve different classes of questions

The search box should stay fast, cheap, and familiar. The assistant should step in when the user needs synthesis across multiple sources, deeper retrieval from sources like publications, or a guided next action.

OpenSearch

Best at high-speed discovery over what is already indexed

Use OpenSearch for the first pass: fast matching, autosuggest from current portal phrases, lightweight semantics via synonym configuration, and low operating cost.

  • Fast response time for common lookups and filtering
  • Autosuggest can reflect current portal vocabulary and phrases
  • Some semantic flexibility through synonym and ranking configuration
  • Cheaper path for broad everyday search traffic
Best Fit

Known-item search, simple metadata lookups, faceted browsing, and "get me to the right page quickly" interactions.

AI Portal Assistant

Best when the answer has to be assembled, compared, explained, or acted on

The assistant can pull from multiple knowledge bases at once, including the knowledge graph and publication content that is not available in OpenSearch, then recommend what the user should do next.

  • Combines multiple knowledge bases, including the knowledge graph
  • Can use publication content that is not indexed in OpenSearch
  • Stronger on analytical questions and multi-step reasoning
  • Can retrieve deeper data, not only surface-level metadata
  • Can integrate external knowledge sources when portal context is not enough
  • Can take actions such as navigating on the user's behalf
  • Can suggest sensible next steps after answering the question
Best Fit

Cross-source synthesis, comparisons, explanation-heavy workflows, exploratory analysis, and guided task completion inside the portal.

Sage Brain

The same Portal Copilot interface can also power Sage Brain

The NF Portal Assistant demonstrates the interface pattern. `Sage Brain` can use the same Portal Copilot experience, but with a much more sophisticated knowledge graph and both a broader and deeper scientific knowledge base behind it.

Same Interface

Portal Copilot can stay consistent while the underlying knowledge becomes far richer

  • Reuse the Portal Copilot interaction model for search, explanation, and next-step guidance
  • Apply the same chat-driven pattern across program boundaries instead of limiting it to one disease portal
  • Support scientific question answering, exploratory analysis, and hypothesis generation in one interface
What Sage Brain Adds

A larger and more connected graph-backed scientific substrate than the NF portal alone

  • Much more sophisticated knowledge graph structure
  • Adds (re)processed data, not only metadata
  • Additional ontologies and curated cross-program connections
  • All publications, computational tools, governance, and policy context
  • Scientific reasoning across genes, clinical traits, and other entities
Sage Brain

A richer knowledge foundation enables a new class of questions

Science Workstream

How a scientific user might use Sage Brain

  • Generate new hypotheses by connecting signals across genes, traits, diseases, and analytical results.
  • Understand new knowledge gaps by seeing where evidence is thin, inconsistent, or missing across programs.
  • Find the most relevant processed data and literature without starting from raw metadata alone.
  • Ask broader scientific questions that cut across program boundaries instead of staying inside one portal or disease area.
